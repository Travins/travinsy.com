数值滑块的三档尺寸是 28、32、36px。放在一起看，它们几乎一样高，我觉得区分度不够。这个判断让我多走了一段路。

## 方条

[数值滑块](/components/value-slider/)是这一系列的起点。标签和读数都放在轨道里，拖出两端会有一点过冲，松手弹回来。外观也是那时候定的：细边框，小圆角，淡色底，填充是一层淡淡的色调，手柄是一道竖线，不用圆点。它看上去更像仪表上的一格，不像常见的圆形滑块。我管它叫“方条”。

后面的[分段选择](/components/segmented-control/)、[开关](/components/toggle-switch/)、[色调选择](/components/tone-picker/)和[角度刻度尺](/components/angle-dial/)都是照着方条做的。要把它们放进同一个面板，先得高度一致，所以有了这张表：

| 档位 | `sm` | `default` | `lg` |
| --- | --- | --- | --- |
| `bar` | 28px | 32px | 36px |
| `compact` | 18px | 22px | 24px |

每个控件的变量名各不相同，数字都从这张表里取。放进一个面板，不用再手动对齐。

## 撤掉的 pill 和 line

回到开头那个问题。三档只差 4px，我就给滑块加了一个 `variant`：`pill` 是圆角粗轨加实色填充，`line` 是一根细线，两个都配圆形手柄。

做出来一看，就是随处可见的那种滑块。竖线和淡色填充没了，方条的样子也就没了。更麻烦的是，它们和后面要补的开关、分段选择也对不上。

这两个变体在同一天被我撤掉，换成现在的 `bar / compact / slim`。三档都是方条，边框、填充、竖线一样不改，只改高度。`slim` 的轨道矮到放不下字，标签就挪到上方，竖线比轨道高出一截。我放弃了“粗细一眼就能分开”，换来的是三档放在一起，还认得出是一个系列。

## 一个个改掉的细节

分段选择的第一版，标题是方条最左边一个独立的格子，用竖线和选项隔开。用起来才发现，它很容易被当成第一个选项。现在标题改成了纯文字，位置和样式都跟滑块、开关的标签一样；选项挪进右边一道下凹的槽里，选中的那一项凸起来。后来我又去掉了槽和选中块上的描边，因为外框、凹槽、选中块三层线叠在一起太乱。现在凹槽只用浅底色，选中块靠背景色和一点阴影浮起来。

<ComponentPreview name="segmented-control-demo" />

开关一开始也用了竖线手柄，想让它和滑块长得一样。可开关只有开和关两种状态，竖线停在左边还是右边，没有圆点一眼看得明白。我最后把它改成了胶囊轨道加圆形手柄，打开时轨道变实色，整条也从左往右铺上淡色。这样系列里就有了两种手柄：滑块的值是连续的，用竖线；开关只有两态，用圆点。硬让两者同形，反而说不清状态。

<ComponentPreview name="toggle-switch-demo" />

滑块拖得再顺，想设一个精确的数还是得输入，所以读数可以点开直接改。第一版的输入框带边框，聚焦时外面还套着滑块整条的焦点环，一圈套一圈。我改了两处：滑块整条的焦点环只在手柄被键盘聚焦时出现；输入框去掉边框，改成一小块背景色，外面一圈色调细描边。

## 面板不该抹平示例

控件齐了，[控制面板](/components/control-panel/)把它们装在一起，标题栏上有“恢复”和“复制”两个按钮。复制出来的是一段 JSX，只写你相对默认值改过的那几项。组件文档的每个示例下面也能展开一块这样的调整面板，示例本身不用改。

最早所有示例共用一份面板配置，后来出了问题。面板的覆盖会作用到示例里的所有实例，可很多示例是故意让几个实例取不同值的。走马灯有个示例放了两条彩带，一条往正方向倾斜，一条往负方向，滚动方向也相反。面板里要是有“旋转”和“反向”，一拖，两条彩带就变成一样的了，这个示例想说明的东西也跟着没了。

所以配置改成可以按示例收窄：

```ts title="tuner/marquee.tsx"
examples: {
  // 两条彩带一正一负倾斜、方向相反
  "marquee-demo": { omit: ["rotate", "reverse"] },
}
```

代码改完还不够。现在验收时要一个个示例看过去，确认面板里没有会破坏示例的控件，这一条我写进了验收技能。

首页首屏那块“调一调”就是用这些拼的：一块[二维板](/components/xy-pad/)调视角，两条分段选择换材质和地面，一排色点换色调，一个开关管音效。窄屏放不下时，它会收成一个按钮，按钮上就写着“调一调”。
