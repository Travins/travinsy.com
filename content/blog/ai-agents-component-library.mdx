自动化 QA 脚本一排全绿，Pi 交回来的验收结论却是「不通过」。

它抓到三个阻塞问题：骨架的 CSS 被构建配置当成全局样式，延迟没生效；图表占位把排名图撑高了 433px；列表缩略图的骨架高度是 0（经过见[上一篇](/blog/static-site-loading/)）。脚本只查我想到要查的事，Pi 是真在页面上看了一遍。后来我给每类问题都补了一条断言，也不再把实现者说的「完成了」当证据。

10 月 25 日到 28 日，这个站一共 197 个提交，组件、文档、区块、模板、主题、验收脚本都有，代码不全是一个模型写的。主控 Agent（Claude Opus 5.5）拆任务、做审查，Claude Sonnet 5.5 和 Codex 写核心代码，Pi（DeepSeek-V4.1-Flash）干批量的活，最后由主控统一提交。

## 按出错代价派活

分工我不按谁更强来分，按写错了有多疼来分。改错一个 demo，坏的是一个示例页；改错布局原语，整站都跟着歪。所以布局原语、主题系统、复杂交互交给 Sonnet 或 Codex，两边互为替补，哪边额度多先用哪边。组件的 MDX 文档和 demo 交给 Pi：第一篇写好，模式就定了，后面照着抄，错了也好改。

主控很少亲自写代码，只在任务要跨模块判断，或者子任务连着失败两次时才动手。

## 说明写清楚，范围别重叠

子 Agent 看不到我和主控之前聊过什么，手里只有一段任务说明。目标、先读哪些文件、能改哪些路径、怎样算完成，缺一项它就只能自己猜。

它也不记得上一次的约定，每次都从零开始。所以规范不能靠口述，我把它们写成 `.agents/skills/` 下的技能文件，组件怎么写、registry 条目怎么加、网格怎么排、博客怎么润色，各一份。任务说明里只写一句「先读 `component-conventions`」。规范改了也只改一处：像「占位层必须绝对定位，淡出后留下的节点也不能占尺寸」这条，写进去之后，每个读它的子任务都照着做。

范围这条是被 `registry.json` 逼出来的。每加一个组件都要在里面登记，几个子任务同时改，后写的直接盖掉先写的。现在子任务只汇报自己引入了哪些依赖，这个文件由主控统一改。

提交也一样。有一次我在同一个工作区里手改标志和文章，还没改完，主控一个 `git add -A` 把它们混进了两条毫不相干的提交，后来只好一条条拆回来。从那以后子 Agent 一律不提交，主控也只暂存自己动过的路径。

## 「完成了」只是线索

主题页预览区是 Codex 写的，Pi 验收给了个「有条件通过」：灰阶主题在暗色下，堆叠图有一段几乎看不见，对比度只有 1.31:1；视口在 640 到 715px 之间，开关的文字被截断。两个问题都只在特定主题、特定宽度下出现，换个状态就看不到。主控照着修了：图表取色改成亮色用 `chart-2` 到 `chart-5`、暗色用 `chart-1` 到 `chart-4`，下排三列在 `md` 以下退成单列。

数值滑块那次是另一回事。子任务汇报说缩放动画只加在 `Control` 内层，实际代码里是 `motion.div` 把整个 `Control` 包住了，Base UI 换算数值用的矩形会跟着一起缩放。这是 Codex 独立审查时发现的。

那之后我定了几条做法：涉及手感、坐标、可访问性的说法，主控自己翻源码核对；Pi 的产出固定再派 Codex 审一遍，审查时只给代码，不给实现者的结论，免得审查者被结论带着走。验收说明也得写明在哪些主题、哪些宽度、哪些状态下看，验收者能抓到什么，取决于让它看什么，只写「检查一下」是不够的。

机器能查的就交给机器。每一轮的硬门槛是 `pnpm lint`、`pnpm registry:lint`、`pnpm build`，registry 的检查不许有警告。动了视觉和交互的，再跑 `pnpm qa:shots` 批量截图，顺带查水合报错和横向溢出；加载相关的跑 `pnpm qa:loading`。只是开头那次已经说明，脚本全绿也不代表没问题。

独立验收不便宜，每个重要任务要多一轮，有时两轮。可它抓出来的问题，到了线上就是别人的问题，我宁愿在这里多花一轮。

## 推不出去的事

有些事分不出去。一个组件放 `ui` 还是 `blocks`，两个组件的接口怎么对，哪个依赖该登记进 `registry.json`，子任务只看得见自己的目录，判断不了。几个子任务各自都没错，合到一起也可能互相踩脚，所以审查、跑门槛、按路径暂存、提交，最后都落在主控身上。

视觉取舍更是这样。区块改用自研组件那一轮，AI 助手区块里的步骤流程被换成了 Timeline，整段一下子拉得很长。我没让它过：不如原来的 Trace 紧凑。规则就此多了一条，换成自研组件后尺寸不能比原来大。这种事没有标准答案，只能人来看。

三行的小改动，我也不会为了用上分工去写一份说明，直接改更快。

那个区块现在的步骤流程又是 Trace，旁边多了一张紧凑的图表。写完这篇的时候，提交数已经过了 200。
