## 用法

传入过去一年的每日记录即可。顺序随意：组件会按日期排序，并只绘制最后一天往前 365 天。

```tsx title="app/contributions.tsx"
import {
  ContributionGraph,
  type Contribution,
} from "@/components/ui/contribution-graph/contribution-graph"

const data: Contribution[] = [
  { date: "2025-12-30", count: 0, level: 0 },
  { date: "2025-12-31", count: 7, level: 3 },
]

export function Contributions() {
  return <ContributionGraph data={data} />
}
```

### 数据形状

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` | `string` | `YYYY-MM-DD`，按 UTC 解析 |
| `count` | `number` | 当天数量，用于悬浮提示与数据表 |
| `level` | `number` | 0–4，只决定方块深浅 |

`level` 与颜色一一对应，语义始终由 `count` 提供；站点构建时从 GitHub 抓取失败也可以直接复用旧数据，组件不会因为空数组而崩溃。

### 文案与区域格式

图例文字、计数单位、数据表表头都是带默认值的中文 props，需要换成别的语言时逐个覆盖即可：

```tsx
<ContributionGraph
  data={data}
  locale="en-US"
  lessLabel="Less"
  moreLabel="More"
  unitLabel="contributions"
  detailsLabel="Show daily contributions"
  regionLabel="Contribution calendar for the past year, horizontally scrollable"
/>
```

`locale` 只影响 `Intl` 的格式化结果：月份表头（`1月` / `Jan`）、星期表头与数字分组（`1,234`）。

### 颜色

五个级别使用 `bg-foreground/5` 到 `bg-foreground/80`，随亮暗模式和颜色主题自动变化，不需要额外的 CSS 变量。

### data-slot 与状态

| 元素 | `data-slot` | 其他属性 |
| --- | --- | --- |
| 根元素 | `contribution-graph` | `data-state="ready"`；无有效数据时为 `empty` |
| 滚动区域 | `contribution-graph-scroll` | `role="region"` |
| 星期表头 | `contribution-graph-weekdays` | — |
| 每日方块 | `contribution-graph-day` | `data-date`、`data-level="0"`–`"4"` |
| 图例 | `contribution-graph-legend` | `role="img"` |
| 数据表折叠区 | `contribution-graph-details` | — |
| 数据表 | `contribution-graph-table` | — |

## 可访问性

- 每个方块是真正的 `<button>`，方向键（上 / 下 / 左 / 右）在相邻日期之间移动焦点，整个日历只占一个 Tab 停靠点。
- 颜色之外还有三种读取方式：`aria-label`（日期 + 次数）、悬浮提示，以及底部的“查看每日贡献数据”表格。
- 星期与月份表头是纯装饰，带 `aria-hidden`，不会被逐字朗读；图例以 `role="img"` + `aria-label` 朗读为一句“贡献数量由少到多”，色块对读屏隐藏。
- 日历容器可横向滚动并带 `tabIndex=0`，窄屏只会滚动不会撑破布局；焦点在方块上时方向键用于在日期之间移动，并用 `preventDefault` 阻止页面跟着滚动。
- 组件没有任何动画，`prefers-reduced-motion` 下表现一致。

## 注意事项

没有有效数据时组件渲染一行静态文案，不会抛错。日期必须是能被 `Date.parse` 解析的完整日期，例如 `2025-12-31`；`2025-12` 这类简写会被过滤掉。

数据只在**构建时**或父组件传入时确定，组件本身不发起请求，符合静态导出的约束。
