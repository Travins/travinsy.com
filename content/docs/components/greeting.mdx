## 用法

默认输出 `你好，很高兴在这里遇见你。`，挂载后会换成与访客时段相符的问候语。

```tsx title="app/greeting.tsx"
import { Greeting } from "@/components/ui/greeting/greeting"

export function Intro() {
  return (
    <h2 className="text-xl font-medium">
      <Greeting />
    </h2>
  )
}
```

需要换文案时传入 `fallback` 与 `suffix`，两者都是纯文本：

```tsx title="app/intro.tsx"
<Greeting fallback="嗨" suffix="，今天想写点什么？" />
```

四个时段的问候语也可以分别覆盖，适合换口吻或多语言，例如把晚上换成更亲近的说法：

```tsx
<Greeting evening="早点休息" suffix="，今天也辛苦了。" />
```

### 时段划分

| 本地时间 | 问候语 | 对应 prop |
| --- | --- | --- |
| 05:00–10:59 | 早上好 | `morning` |
| 11:00–13:59 | 中午好 | `noon` |
| 14:00–17:59 | 下午好 | `afternoon` |
| 18:00–次日 04:59 | 晚上好 | `evening` |

## API

### Greeting

<PropsTable name="greeting" component="Greeting" />

根元素是 `<span data-slot="greeting">`，`data-state` 在挂载前是 `pending`、拿到本地小时后变成 `ready`。

## 可访问性

- 渲染的是内联 `<span>`，可以放进 `<p>`、`<h2>` 等任何文本容器，不改变标题层级。
- 挂载后的文案替换**没有**加 `aria-live`：它是页面的主文案而不是通知，逐字播报会打断读屏用户。确实需要播报时，在外层容器上自己加 `aria-live="polite"`。
- 时段判断只读本地小时，和键盘、焦点、动效无关；组件不含动画，`prefers-reduced-motion` 下表现一致。
- 首屏文案与静态 HTML 一致，读屏和搜索引擎看到的是同一段文字，不会出现空内容。

## 注意事项

### 为什么必须在客户端渲染

问候语取决于访客设备上的 `new Date().getHours()`，服务端渲染时无从得知。静态导出会把 HTML 在构建时生成一次，如果首屏直接用浏览器时间渲染，客户端水合时拿到的文本就会和 HTML 不一致。

组件因此把 `fallback` 作为初始文案，挂载后再由 `useEffect` 替换，并每分钟校准一次。

<Callout variant="tip" title="把 fallback 写成中性问候">
  副作用是首屏会短暂显示 `fallback`：把它设成一句中性、通用的问候（例如默认的“你好”）就不会显得突兀。
</Callout>

### 文案与结构

- `fallback`、`suffix` 与四个时段文案都是纯字符串，不接受 JSX。需要强调某一段时，在外层用 `<span>` 包裹。
- 时区以访客设备为准，不做服务端时区推断，因此不需要 `timeZone` 参数。
- 组件返回内联 `<span>`，不是块级容器；需要自己的布局时在外部套一层元素。
