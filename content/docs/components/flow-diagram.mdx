上图是一条 AI 应用的全链路：Web、App、CLI 三个入口错开发出请求，经网关进入 Agent；Agent 并行调度知识库、工具与大模型，三路耗时各异；结果汇总后沿原路送回每个入口。入口蓝、Agent 紫、三类能力各一种颜色、返回的结果绿，用到了图标节点、点亮、加载圈与状态点、常驻连线的流动纹理和方格底纹。

提炼自本站首页「我在做什么」里的三幅小插画。它不是一个“传数据就出图”的图表组件，而是一组 SVG 原语：你按设计坐标摆节点、连线、写标签，再给每一步指定出现的时刻，整张图就会按这条时间轴循环播放。

## 用法

一张图由 `FlowDiagram` 外框和里面的原语组成。所有坐标都落在 `width × height` 的设计画布上，显示时整体等比缩小，所以 `FlowDiagram` 的宽度交给 `className` 控制即可。

```tsx title="app/pipeline.tsx"
import {
  FlowBeam,
  FlowDiagram,
  FlowNode,
  flowArrival,
  flowRoute,
} from "@/components/ui/flow-diagram/flow-diagram"

// 路径在组件外创建：长度要提前算出，光点的到达时刻靠它换算
const TO_PROCESS = flowRoute([[80, 50], [130, 50]])
const PROCESS_AT = flowArrival(0.5, TO_PROCESS)

export function Pipeline() {
  return (
    <FlowDiagram width={320} height={100} duration={4.4} exit={3.6} rest={3.4} className="w-full max-w-md">
      <FlowBeam route={TO_PROCESS} at={0.5} />
      <FlowNode x={50} y={50} width={60} litAt={0.2} label="输入" />
      <FlowNode x={160} y={50} width={60} litAt={PROCESS_AT} label="处理" />
    </FlowDiagram>
  )
}
```

约定很少：

- **节点是容器。** `FlowNode` 画边框和点亮效果；简单的“图标 + 文字”直接用 `icon`、`label`、`description`，它们会整体居中。复杂内容（加载圈、状态点、进度条……）作为子元素按绝对坐标摆放，通常用 `FlowLabel` 或 lucide 图标（SVG 里直接给 `x`、`y`、`width`、`height` 即可）。
- **点亮时刻来自光点。** 光点出发的时刻 `at` 加上路径长度除以速度，就是它抵达的时刻，`flowArrival(at, route)` 帮你算好，直接传给目标节点的 `litAt`。
- **连线默认跟着光点一路长出来。** `FlowBeam` 的底线从起点生长到终点，光点走到哪线画到哪，到达时节点点亮；常驻的数据流还可以再加 `flow`，详见「连线动态」。
- **颜色来自主题变量。** 默认点亮用 `primary`，其他色调用 `tone` 指定，亮暗模式和颜色主题切换后自动跟随，详见「色调」。

## 时间轴

一张图只有一个时钟：从 `0` 走到 `duration` 秒，到头回到 `0` 重新开始。所有元素都是这个时间的函数，没有各自的定时器，所以不同元素之间不会错位。

<TypeTable
  type={{
    at: { type: "number", description: "元素出现 / 光点出发的时刻（秒），各原语的叫法略有不同：`FlowBeam` 的 `at`、`FlowNode` 的 `litAt`" },
    exit: { type: "number", description: "这一刻起所有元素一起淡出，到 `duration` 时完全消失，下一轮从空白重新开始", default: "duration - 0.8" },
    rest: { type: "number", description: "静帧时刻：首帧、服务端渲染和“减少动态效果”下显示的画面", default: "exit - 0.2" },
    duration: { type: "number", description: "一轮循环的总时长（秒）", default: "8" },
  }}
/>

三者的关系是 `最后一个元素出现 < rest < exit < duration`。

- **`rest` 要选在“画面完整”的一刻**：所有节点都已点亮、没有光点在飞。减少动态效果时图示会永远停在这一帧，所以它就是图示的“封面”。
- **`exit` 和 `duration` 之间留出淡出的时间**，默认 0.8 秒。
- **时刻不用手写死。** 光点到达时刻用 `flowArrival(at, route)` 推算，下一步从上一步的时刻加一点间隔算出来；示例里的 `REST`、`EXIT`、`DURATION` 都是这样级联得到的，改一个起点，后面自动顺延。

### 播放与暂停

- 进入视口（可见面积达到 40%）才开始走，离开视口立即暂停，不占 CPU。
- 初始时钟停在 `rest`，所以服务端渲染的静态 HTML、首帧水合结果、减少动态效果下的画面是同一帧，不会闪一下，也没有水合不一致。
- 切回标签页后时钟从原地继续，不会一下子跳过一大段。
- 开启系统的“减少动态效果”时不播放，也不显示光点，画面固定在 `rest`，连线都是完整的（带 `flow` 的线停在一帧虚线纹理上）。

循环、触发时机、暂停和速度都可以配置，见下面的「播放控制」。

### 自定义动画元素

`useFlowClock()` 返回 `{ time, duration, exit }`，`time` 是 motion 的 `MotionValue<number>`。用 `useTransform(time, 输入区间, 输出区间)` 就能把任何属性绑到时间轴上：

```tsx
function Progress() {
  const { time, exit, duration } = useFlowClock()
  const scaleX = useTransform(time, [2, 3.5], [0, 1])
  const opacity = useTransform(time, [exit, duration], [1, 0])
  return (
    <motion.g style={{ opacity }}>
      <motion.rect
        x={80} y={92} width={100} height={3}
        className="fill-primary"
        style={{ scaleX, transformBox: "fill-box", transformOrigin: "left" }}
      />
    </motion.g>
  )
}
```

别忘了在 `exit` 到 `duration` 之间把元素淡出，否则它会在下一轮开头突然消失。需要在渲染里读取时间做判断时，请像 `FlowTypedText` 那样用 `useMotionValueEvent`，不要在渲染期间调用 `Date.now()`，那会让服务端和客户端的结果对不上。

## 色调

`tone` 决定“亮起来是什么颜色”。`FlowNode`、`FlowDiamond` 点亮后的描边与淡底色、`FlowBeam` 的光点与流动纹理、`FlowEdge`、`FlowSpinner`、`FlowStatusDot`、`FlowTypedText` 的光标，以及可选的 `FlowLabel` 文字，都接受同一个 `tone`：

```tsx
<FlowBeam route={TO_API} at={1} tone="blue" />
<FlowNode x={160} y={50} width={72} tone="green" litAt={1.4} label="API" />
<FlowLabel x={160} y={80} tone="muted">200 OK</FlowLabel>
```

<ComponentPreview name="flow-diagram-tones-demo" />

### 内置色调

| 名称 | 取值 | 说明 |
| --- | --- | --- |
| `primary` | `var(--primary)` | 默认。随颜色主题变化 |
| `foreground` | `var(--foreground)` | 最醒目的中性色 |
| `muted` | `var(--muted-foreground)` | 弱化的中性色 |
| `destructive` | `var(--destructive)` | 失败、拒绝 |
| `blue` `green` `amber` `rose` `violet` `cyan` | `var(--flow-blue)` 等 | 多彩色调，不随颜色主题变化 |

多彩色调来自六个 CSS 变量，由 registry 条目的 `cssVars` 提供亮 / 暗两套 oklch 值，`shadcn add` 时会写进你的全局样式（本站已经在 `globals.css` 里同名定义）：

| 变量 | 亮色 | 暗色 |
| --- | --- | --- |
| `--flow-blue` | `oklch(0.56 0.2 258)` | `oklch(0.72 0.15 255)` |
| `--flow-green` | `oklch(0.62 0.16 150)` | `oklch(0.77 0.17 152)` |
| `--flow-amber` | `oklch(0.7 0.16 70)` | `oklch(0.82 0.15 82)` |
| `--flow-rose` | `oklch(0.62 0.21 5)` | `oklch(0.74 0.16 8)` |
| `--flow-violet` | `oklch(0.56 0.22 292)` | `oklch(0.74 0.15 295)` |
| `--flow-cyan` | `oklch(0.66 0.12 215)` | `oklch(0.82 0.11 208)` |

想换成品牌色，在全局样式里覆盖这些变量即可，所有用到它的图示一起变：

```css title="app/globals.css"
:root {
  --flow-blue: oklch(0.6 0.2 250);
}
.dark {
  --flow-blue: oklch(0.75 0.14 250);
}
```

### 任意颜色

`tone` 也接受任意 CSS 颜色，不在内置名里的字符串都按颜色处理（所以内置名拼错了也不会报错，只是颜色失效）：

```tsx
<FlowBeam route={TO_API} at={1} tone="#ff6a00" />
<FlowNode x={160} y={50} width={72} tone="oklch(0.7 0.2 150)" litAt={1.4} label="API" />
<FlowNode x={260} y={50} width={72} tone="var(--brand)" litAt={1.8} label="CDN" />
```

### 继承

所有原语只读一个 CSS 变量 `--flow-tone`，它沿 DOM 往下继承，所以不用在每个元素上重复写：

- `FlowDiagram` 的 `tone` 是整张图的默认色调（默认 `primary`）；
- `FlowNode` 指定了 `tone` 后，节点里没有单独指定色调的加载圈、状态点、光标都跟着变，图标也会染成这个颜色；
- 元素自己的 `tone` 优先。

自己写的 SVG 元素也可以用：`flowToneStyle("green")` 返回 `{ "--flow-tone": ... }`，放到 `style` 上，里面用 `fill-(--flow-tone)`、`stroke-(--flow-tone)/40`、`text-(--flow-tone)` 取色。

### 连线的颜色

连线默认是中性的前景色。给 `FlowBeam` 或 `FlowEdge` **明确指定** `tone` 后，生长的底线、虚线也会淡淡染上这个颜色（30% 不透明度）；继承自 `FlowDiagram` 的默认色调不会染线。

## 背景

`FlowDiagram` 的 `background` 选择外框的底纹，默认是向四周淡出的点阵：

<ComponentPreview name="flow-diagram-background-demo" />

```tsx
<FlowDiagram background="grid" />         {/* 方格 */}
<FlowDiagram background="none" />         {/* 不要底纹 */}
<FlowDiagram background="dots" fade={false} /> {/* 点阵铺满，不淡出 */}
<FlowDiagram background={<MyPattern />} />      {/* 自己的底纹元素 */}
<FlowDiagram background="none" backgroundClassName="bg-muted/40" />
```

- 内置底纹：`dots` 点阵、`grid` 方格、`lines` 横线、`hatch` 斜纹、`none` 无。点阵与斜纹用 `grid-layout` 提供的 `bg-dots`、`bg-hatch`，方格与横线直接用线条颜色 `--edge` 画渐变，所以都不需要额外的工具类，安装 `grid-layout` 就够了。
- `fade` 控制底纹是否向四周淡出（默认淡出），让图示像摆在图纸上；贴着边框铺满时设为 `false`。
- 传一个元素给 `background`，它会被放进铺满外框的绝对定位层（带 `pointer-events-none`），受 `fade` 影响；`backgroundClassName` 追加到这一层上，调透明度、换颜色，或者配合 `background="none"` 写一个纯 CSS 的底纹。
- 底纹颜色用的是线条颜色 `--edge`，随亮暗模式和颜色主题变化。

## 播放控制

<ComponentPreview name="flow-diagram-playback-demo" />

```tsx
<FlowDiagram loop={false} />                  {/* 只播一遍，停在 rest */}
<FlowDiagram trigger="always" />              {/* 不管是否在视口里都播 */}
<FlowDiagram paused={paused} speed={1.5} />   {/* 外部控制暂停与速度 */}
```

- `loop`（默认 `true`）：设为 `false` 时从头播一遍，走到 `rest` 就停在那一帧，不再淡出重来。因为首帧是 `rest` 静帧，所以单次播放开始时会从完整画面跳回起点再播；想重播，给 `FlowDiagram` 换一个 `key`。
- `trigger`（默认 `"in-view"`）：`in-view` 进入视口才播、离开暂停；`always` 只要没暂停就一直播。
- `paused`（默认 `false`）：暂停，画面停在当前这一刻；还没开始播时就是 `rest` 静帧。可以由外部状态控制，例如“悬停时暂停”。
- `speed`（默认 `1`）：整条时间轴的速度倍率，2 是两倍速，0.5 是半速。`duration`、`exit`、`rest` 等仍然按原速的秒数写。

不论怎么配置，三条保证不变：离开视口暂停、“减少动态效果”下固定在 `rest`、渲染期间不依赖随机数（水合稳定）。

## 布局

画布尺寸由 `width`、`height` 决定，子元素的坐标都以它为准；`fit` 决定显示时怎样适应外框：

- `scale-down`（默认）：只缩小不放大。外框比画布窄时等比缩小，宽时保持设计尺寸并居中，文字大小不会超过设计值；
- `contain`：等比缩放到刚好装进外框，外框更宽时会放大，适合让图示填满一个格子；
- `none`：始终保持设计尺寸，装不下的部分被外框裁掉。

外框的宽高交给 `className`：`w-full max-w-md`、`h-48`、`aspect-video` 等都可以，外框本身没有边框和固定高度。

## 连线动态

连线的两种动态都由同一个时间轴推导，没有独立的 CSS 动画或定时器，所以同样会在离开视口时暂停、在“减少动态效果”下停在 `rest` 这一帧（此时连线完整）。

### 生长

`FlowBeam` 默认 `line="draw"`：底线从起点沿路径画出来，长度正好跟随光点头部，光点走到哪线画到哪，所以目标节点的 `litAt` 一到，线也刚好抵达。线画完后保持完整，到 `exit` 才随循环淡出，下一轮从空白重新生长。

- 生长之前会留一条很淡的虚线（`foreground/10`）当引导，画面不会空着；不需要时传 `guide={false}`。
- 并行分支用同一个 `at` 出发，会同时开始生长，短的先到。
- 同一条线上的重复脉冲照旧用 `base={false}`，只有第一次负责生长，线不会重复画。
- 想保留旧的写法（整条线一开始就在、不随循环淡出），用 `line="static"`。

不带光点的 `FlowEdge` 传了 `at` 也是默认生长，用时 `drawDuration` 缺省按光点的飞行速度由路径长度换算，和光点线的节奏一致；`reveal="fade"` 可以改回整条淡入。虚线（`dashed`）没法分段生长，会自动改成淡入。

```tsx
<FlowEdge route={BACKUP} at={2.4} />                {/* 生长，2.4 秒开始 */}
<FlowEdge route={BACKUP} at={2.4} drawDuration={1} /> {/* 指定用时 */}
<FlowEdge route={BACKUP} at={2.4} reveal="fade" />   {/* 整条淡入 */}
```

### 流动

给连线加 `flow`，画好之后线上会出现持续向前的虚线纹理，像数据在管道里流动，用来表示“常驻连接 / 持续的数据流”，例如推理引擎到各个服务的出口、数据源到清洗。纹理的颜色跟随 `tone`，速度是 `FLOW_LINE_SPEED`（14 像素/秒），比光点慢得多，只是一点克制的呼吸感；方向沿路径从起点指向终点。它在连线画完后淡入，到 `exit` 随循环淡出。

```tsx
<FlowBeam route={TO_API} at={1.7} flow />
<FlowEdge route={TO_API} at={1.7} flow />
```

`flow` 按条开启：同一条线上重复脉冲的几个 `FlowBeam`，只在负责画线的那一个上设置，避免两层纹理叠在一起。

### 路径工具

```ts
function flowRoute(points: readonly FlowPoint[], radius?: number): FlowRoute
function flowArrival(at: number, route: FlowRoute): number
const FLOW_BEAM_SPEED: number // 110，光点飞行速度，单位：设计像素 / 秒
const FLOW_LINE_SPEED: number // 14，连线上流动纹理的速度，单位：设计像素 / 秒
function flowTextWidth(text: string, fontSize?: number): number // 估算文字宽度
function flowToneStyle(tone?: FlowTone): CSSProperties | undefined // 见「色调」
```

`flowRoute` 把折线变成圆角路径并算出长度，`radius` 是拐角半径（默认 6）。它是纯函数，请在组件外调用。`flowArrival` 返回光点抵达终点的时刻。它们和 `FLOW_BEAM_SPEED` 都定义在不依赖 React 的 `route.ts` 里。`flow-diagram.tsx` 是客户端模块，服务端组件不能直接调用它再导出的函数：要在服务端组件里算路径，请改从 `route.ts` 引入；在带 `"use client"` 的文件里（案例都是这样）从 `flow-diagram.tsx` 引入即可。`FLOW_BEAM_SPEED` 在需要“让几束光点同时到达”时有用：`出发时刻 = 到达时刻 - route.length / FLOW_BEAM_SPEED`，参见微服务和 MCP 案例。

```ts
type FlowPoint = readonly [x: number, y: number]
type FlowRoute = { d: string; length: number }
type FlowToneName =
  | "primary" | "foreground" | "muted" | "destructive"
  | "blue" | "green" | "amber" | "rose" | "violet" | "cyan"
type FlowTone = FlowToneName | (string & {}) // 内置名，或任意 CSS 颜色
type FlowBackgroundName = "dots" | "grid" | "lines" | "hatch" | "none"
type FlowFit = "scale-down" | "contain" | "none"
type FlowNodeShape = "pill" | "box"
```

`flowTextWidth` 按“拉丁字符 6px、中文 10px”（10px 字号）线性估算文字宽度，`FlowNode` 用它把图标和文字整体居中，`FlowTypedText` 用它摆光标；自己写需要对齐文字的元素时也可以用。

## 可访问性

- 默认整个图示 `aria-hidden`，读屏完全忽略，适合作为纯装饰。传入 `label` 后外框变成 `role="img"` 并带上 `aria-label`，内部的 SVG 内容不会再被逐个朗读，所以 `label` 应该概括整张图在讲什么，例如“请求从网关扇出到三个服务再汇合”。
- 图示不承载任何交互，没有可聚焦元素。
- 开启系统的“减少动态效果”时没有任何运动，画面固定在 `rest` 这一帧，信息完整。
- 状态不只靠颜色：失败分支除了红色还有 “401” 之类的文字，完成状态有对勾。

## 注意事项

- 画布按设计尺寸绘制，窄屏时整体缩小，文字也会跟着缩小。设计时留意最窄的容器：10px 的文字缩到 0.7 倍就接近 7px，宽度小于 300px 的场景请把画布设计得更窄一些。
- 文字使用等宽字体，`FlowTypedText` 的光标位置按“拉丁字符 6px、中文 10px”估算，混排时请留一点余量。
- 底纹依赖 `grid-layout` 提供的 `bg-dots`、`bg-hatch` 和 `--edge` 变量，安装时会一并装上；不需要底纹时传 `background="none"`。
- 多彩色调依赖 `--flow-blue` 等六个变量。如果你的项目是手动安装、没有经过 `shadcn add`，需要自己把它们加进全局样式，否则这些色调的元素不会显示颜色。
- `tone` 里不是内置名的字符串都按 CSS 颜色处理，写错内置名（例如 `"bleu"`）不会报错，只是颜色失效。
- 路径只支持直线和圆角，拐角由 `flowRoute` 的 `radius` 控制；复杂曲线请自己写 `path` 并放进 `FlowReveal`。
- 生长依赖路径长度的估算，圆角处有一两像素的误差，不影响观感；同一路径的光点与线头始终同步，因为两者用的是同一个长度。
- 外框默认没有边框和固定高度，首页的用法是 `className="h-48 border-b border-edge"`。
