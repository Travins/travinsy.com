## 用法

```tsx title="components/address-form.tsx"
import { RegionPicker } from "@/components/ui/region-picker/region-picker"

export function AddressForm() {
  return (
    <RegionPicker
      name="region"
      required
      regions={() =>
        import("@/lib/china-regions").then((m) => m.chinaRegions)
      }
    />
  )
}
```

`value`、`defaultValue`、`onValueChange` 的值都是**一个代码字符串**（最末一级的 `code`），没选时是 `null`。`onValueChange(code, path)` 的第二个参数是从最顶层到它的完整路径，需要名称时不用自己再查。

```tsx
<RegionPicker
  regions={regions}
  value={code}
  onValueChange={(code, path) => {
    setCode(code)
    console.log(path.map((node) => node.name).join(" / ")) // 浙江省 / 杭州市 / 西湖区
  }}
/>
```

### 数据标准

`regions` 接收一棵树，节点结构就是组件认的「标准」，任何符合它的数据都能用：

```ts
type RegionOption = {
  code: string // 全树唯一，也是组件对外的值
  name: string // 显示名称
  pinyin?: string // 无声调拼音，音节用空格分隔："hang zhou shi"
  children?: RegionOption[] // 没有或为空数组 = 末级
}
```

- **层级深度不固定**。直辖市只有「市 → 区」两级（北京市 → 东城区），东莞、儋州这类不设区的市，以及香港、澳门没有下级。选到没有 `children` 的节点就选完了，组件不会凭空造出一层同名节点。
- **`pinyin` 可以没有**。没有时搜索只按名称和代码；有的话才支持全拼和首字母。
- **`code` 不必是国标码**，任何字符串都行，只要在整棵树里唯一。

组件的类型叫 `RegionOption`，和 `china-regions` 的 `ChinaRegion` 结构相同，TypeScript 按结构兼容，直接传即可。

### 惰性加载

`regions` 可以是数组，也可以是返回 Promise 的函数。官方数据有 3214 条、约 200KB，打进首屏很不划算，推荐写成动态 `import()`：

```tsx
<RegionPicker
  regions={() => import("@/lib/china-regions").then((m) => m.chinaRegions)}
/>
```

函数形式的调用时机：

- 用户**第一次打开**浮层时调用；
- 如果已经有初始值（`value` / `defaultValue` 非空），需要显示「浙江省 / 杭州市 / 西湖区」，则**挂载后**就调用，不用等打开；
- 只调用一次，之后复用结果。每次渲染都写内联箭头函数也不会重复请求。

加载中，触发器显示「正在加载地区数据…」（有 `fallbackLabel` 时显示它），浮层里是加载提示；失败时浮层显示错误和「重试」按钮。数组形式则没有这些状态。

数组形式请保持引用稳定（放在组件外，或 `useMemo`），否则每次渲染都会重建搜索索引。

### 值存代码，不存名称

只存一个 `code`，是因为它短、稳定、能进数据库的索引，完整路径随时可由数据反查：

- 名称会改（「县」改「区」），代码在改名后一般不变；
- 一个代码就能还原三级，不会出现「省存了、市存了、区对不上」的半截数据；
- 表单提交、接口入参只有一个字段。

后端回显或导出时把代码转成名称，用 `findRegionPath`（纯函数，服务端可用）：

```ts
import { findRegionPath, formatRegionPath } from "@/components/ui/region-picker/utils"
import { chinaRegions } from "@/lib/china-regions"

const path = findRegionPath(chinaRegions, "330106")
formatRegionPath(path) // "浙江省 / 杭州市 / 西湖区"
formatRegionPath(path, "") // "浙江省杭州市西湖区"
path.map((node) => node.name) // ["浙江省", "杭州市", "西湖区"]
findRegionPath(chinaRegions, "999999") // []，找不到返回空数组
```

### 代码失效时

行政区划会调整：地区被撤销、合并，或者你的数据版本比存下来的旧。这时代码在数据里找不到。触发器不会空白，而是：

- 显示 `fallbackLabel`——调用方保存数据时**一并存下的名称**，用户看到的仍是当时选的地址；
- 没传 `fallbackLabel` 就显示「未知地区（330199）」。

```tsx
<RegionPicker
  regions={regions}
  value={order.regionCode}
  fallbackLabel={order.regionName}
/>
```

用户重新打开选择，选了新的值，`fallbackLabel` 就不再用到。建议保存地址时同时存 `code` 和当时的名称。

### 搜索

搜索框在**任意层级**命中，结果显示完整路径并高亮命中部分：

| 输入 | 命中 |
| --- | --- |
| `杭州`、`西湖` | 名称包含 |
| `hangzhou`、`hang zhou` | 全拼，去掉空格后匹配 |
| `hz` | 拼音首字母 |
| `3301` | 代码前缀 |
| `杭州 西湖`、`浙江 杭州`、`hangzhou xihu` | 带路径：最后一个词命中本级，其余的词命中本级或任一上级 |

排序：完全匹配与开头匹配优先，同级时层级浅的优先，再同级保持数据里的顺序；最多显示 50 条，超出时列表下方提示缩小范围。选中末级节点直接确认；选中非末级节点则跳到它的下级继续选。

输入拼音时，输入法组词阶段的回车与方向键不会被当作列表操作。

### 限制层级与选到中间级

- `depth={2}`：最多选到第 2 级（省市），到达这一级的节点视为末级。
- `allowPartial`：允许不选到底。浏览到非顶层时，底部出现「选择「浙江省」」按钮，直接确认当前路径。

## 界面与适配

设计参照了 Vant、TDesign、NutUI 的移动端级联选择与 Ant Design 的桌面级联，取它们共同的三点：**分步、选完自动前进、点已完成的步骤回退**。

- **手机与触屏设备**（视口窄于 640px，或 `pointer: coarse`）：从底部弹出面板，高 85% 视口。
  - 顶部标题栏：「选择地区」、清除（有值且非必填时）、关闭。
  - 下面是竖排步骤条：①省份 ②城市 ③区县，每步一行 44px；已完成的打勾、可点回去，当前步垫底色，后面的步骤灰显。
  - 选项单列整行，每行 44px；超过 16 项时按拼音首字母分组，组标题吸顶，右侧有字母索引条，点一下跳到对应字母。
  - 搜索框不自动聚焦，免得软键盘弹出来盖住列表；底部留出安全区。
- **桌面**：输入框下方弹出浮层，宽 30rem（不小于触发器、不超出视口）。
  - 步骤条横排在顶部，搜索框打开即聚焦。
  - 选项是带边框的紧凑按钮；分组时按字母两栏排布。
  - 内容区固定 16rem 高，超出滚动。每一步选项多少不一，高度固定后浮层不会在输入框上下方之间来回翻转。
- 用 `presentation` 固定形态（`"sheet"` / `"popover"`），默认 `"auto"` 按上面的规则自动切换；`container` 把底部面板挂进指定元素，只盖住它、不锁整页滚动，适合预览窗格、手机外框这类局部区域。
- **步骤数一开始就显示**：数据最深三级就显示三步；选了直辖市后剩两步，第二步名称自动对齐为「区县」（`labels.levels` 从最深一级往上对齐）。
- 选完一步自动进入下一步，最后一步选完即确认并关闭；换步骤时列表向前或向后滑入，系统开启「减弱动态效果」时不播放。
- 搜索时步骤条暂时隐藏，结果单列显示完整路径与代码。

### 工具函数

都在 `region-picker/utils.ts`，没有 `"use client"`，服务端组件和 Route Handler 里可以直接用。

```ts
// 按代码找完整路径，找不到返回 []
function findRegionPath(regions: RegionOption[], code: string): RegionOption[]

// 路径转文字，默认用 " / " 连接
function formatRegionPath(path: RegionOption[], separator?: string): string

// 一次性搜索，每次调用都重建索引；返回命中节点、完整路径、各级高亮区间
function searchRegions(
  regions: RegionOption[],
  query: string,
  options?: { depth?: number; limit?: number }, // limit 默认 50
): RegionSearchResult[]

// 高频搜索：先建一次索引，再反复查
function createRegionIndex(regions: RegionOption[], options?: { depth?: number }): RegionIndex
function searchRegionIndex(index: RegionIndex, query: string, limit?: number): {
  results: RegionSearchResult[]
  total: number // 命中总数，results 最多 limit 条
}
```

`searchRegions` 的用法：做一个自己的联想输入，或者在服务端按关键字查地区。

```ts
import { searchRegions } from "@/components/ui/region-picker/utils"

const [first] = searchRegions(regions, "hz xh")
first.path.map((node) => node.name) // ["浙江省", "杭州市", "西湖区"]
```

## 可访问性

- 搜索框是 **combobox**：焦点始终留在输入框，选项通过 `aria-activedescendant` 表达高亮，选项是 `role="option"`，列表是 `role="listbox"`。
- 键盘：`↑` `↓` 逐项移动，搜索框为空时 `←` `→` 也能逐项移动；`Enter` 选择；`Backspace` 在搜索框为空时回到上一步；`Esc` 关闭并把焦点还给触发器。
- 屏幕阅读器：每次换步骤播报「第 2 步，选择城市，共 21 项」，搜索时播报「找到 12 个结果」，通过隐藏的 `role="status"` 区域；步骤条是有序列表，当前步带 `aria-current="step"`；手机面板是带标题的对话框，打开时焦点落在关闭按钮上。
- 触发器是 `button`，带 `aria-haspopup`、`aria-expanded`；可以用 `<label htmlFor>` 或 `aria-label` 命名。
- 焦点环、选项高亮都有可见样式；已选项除了底色，还有对勾（末级）或箭头（非末级）。

## 注意事项

- 触发器是个 `button`，不是文本输入；`required` 的原生气泡提示挂在覆盖其上的隐藏输入，聚焦会转交给触发器。
- 受控模式下记得同时处理 `onValueChange`，否则选择后触发器不更新。
- `depth` 小于已选值所在的层级时，值照常回显完整路径，只是浮层里到不了更深的节点。
- 约 3000 条数据的索引构建与单次搜索都在毫秒级，不需要防抖；数据达到几十万条时请自己换服务端搜索。
