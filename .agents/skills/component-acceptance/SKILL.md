# 组件开发与验收流程

> 写代码的规范见 `component-conventions`，新增条目的文件与构建步骤见 `registry-item`。本技能管的是**从想法到可发布**的过程与验收标准。

## 0. 原则

1. **默认示例是门面**：组件页第一个预览、组件列表缩略图、首页 Bento 用的是同一个默认示例（`<name>-demo.tsx`），三处必须一致。改默认示例时，旧版本不删，挪进内页成为普通示例。
2. **一个示例只讲一件事**：不要并排放几个变体做对比（对比交给调整面板或用户自己改属性）。
3. **能力用属性实现**：示例里出现 `[&_[data-slot=…]]` 这类穿透选择器，说明组件缺一个属性，回去补属性，不要在示例里硬改。
4. **亮色、暗色、颜色主题同等重要**：暗色下“几乎看不见”与亮色下“糊成一片”一样是缺陷。
5. **小步提交、只提交自己的文件**：用 `git add <路径>`，不用 `git add -A`。

## 1. 阶段

| 阶段 | 产出 | 通过标准 |
| --- | --- | --- |
| ① 定位 | 一句话说明组件做什么、和已有组件的区别 | 和现有组件不重叠；能说出它在首页 / 列表里“亮点”是什么 |
| ② 组件 | `src/registry/ui/<name>/`、`registry.json`（含所有文件，如 `sound.ts`） | 遵守 `component-conventions`；属性带 JSDoc 与 `@default` |
| ③ 默认示例 | `<name>-demo.tsx` | 一眼能看出组件最强的能力；在 16:10 列表画框和首页格子里都不溢出、不压字 |
| ④ 内页示例 | 每个能力一个示例 | 互不重复；每个对应 MDX 里一个小节；不依赖其他 registry 组件 |
| ⑤ 文档 | `content/docs/components/<name>.mdx` | 结构固定（见 §4）；文字与当前实现一致 |
| ⑥ 视觉验证 | 截图 | §5 全部通过 |
| ⑦ 交互验证 | 脚本 + 手动 | §6 全部通过 |
| ⑧ 收尾 | 构建、检查、提交 | §7 全部通过 |

## 2. 默认示例的标准

- 背景用站点语言：点阵（`bg-dots`）、方格（`bg-grid`）、线条网格、主题色光晕（`var(--primary)` 混色），**不用固定彩色光晕**。
- 色彩：优先用主题色的深浅（`color-mix(in oklab, var(--primary) N%, var(--background))`），需要多色时用 `--flow-*`；不硬编码颜色。
- 不放与组件无关的装饰：编号标签（`01 / XXX`）、无意义英文角标、框中框。
- 自带满幅背景的示例登记到 `component-preview-client.tsx` 的 `FULL_BLEED`，在列表登记到 `component-thumbnail.tsx` 的 `fillClasses`，铺满不留内边距；卡片类示例在 `preview-backdrop.tsx` 登记点阵 / 方格底纹。
- 放不下时只给列表画框单独缩放（`fitClasses`），不改示例本身。

## 3. 内页示例的标准

- 用知名品牌的标志或真实场景做素材（如 shadcn/ui、Pi、Vercel），比几何方块更有说服力；坐标取自官方图标（`simple-icons`）。
- 每个示例打开一项或两项能力，并在 MDX 小节里点名属性（如「地面用棋盘格 `floor="checker"`」）。
- 对于参数多的组件，提供文档专用的**调整面板**（参考 `src/components/docs/tuner/`：组件导出覆盖 Context 与 `onReport`，在 `tuner/<name>.tsx` 声明控件并登记到 `tuner/index.ts`）：
  - 通过组件导出的 Context 覆盖子树属性，不改示例源码；
  - 未改动的项显示示例的实际取值（组件通过 `onReport` 回报），改动过的高亮；
  - 打开面板时画框固定，**容器高度不变、图形不缩小**；
  - 选项带小样（材质方块等），开关用 `role="switch"`。
  - **逐个示例过一遍面板**：面板的覆盖作用于示例里的所有实例。示例里多个实例刻意取了不同值（正反方向、正负角度、不同色调、只有一处带刻度），或者示例自带同名控件（暂停、倍速），或者示例本身就是某个参数的对比时，在 `tuner/<name>.tsx` 的 `examples` 里登记：`{ omit: [...] }` 去掉这些项，整块不适合调时设为 `false` 关闭面板，并用注释写明原因。

## 4. 文档结构与校对

固定顺序：页首预览 → 安装 → 用法（最小可运行代码 + 关键概念小节）→ 示例 → 原理（可选）→ API（PropsTable、Hook、类型、data-slot）→ 可访问性 → 注意事项 → 源码。

发布前逐段核对：

- 文字里的属性名、默认值、取值列表与源码一致；示例代码可以直接复制运行。
- 删掉过时说法（例如“本页示例都用某个角度”“下方给出属性写法”这类随实现变化的句子）。
- 新增的导出（Hook、类型、Context）都写进 API；新增的 `data-slot` 写进表格。
- 组件 JSDoc 同步更新，PropsTable 从 JSDoc 生成。
- 有新文件时检查 `registry.json` 的 `files`。

## 5. 视觉验收

先 `pnpm build`，再运行：

```bash
pnpm qa:shots <组件名> [更多组件名] [--open]
```

脚本（`scripts/qa-shots.ts`）对 `out/` 起临时静态服务，用系统 Chrome（`CHROME_PATH` 可覆盖）按下表截图，同时检查运行时报错（含 hydration）与横向溢出，生成 `.qa/<时间戳>/index.html` 报告；有问题时退出码为 1。每张截图都要看：

| 场景 | 宽度 | 检查 |
| --- | --- | --- |
| 组件页全部示例 | 1440 / 375 | 不溢出、不重叠、数字不断行 |
| 组件列表缩略图 | 1440 / 768 / 375 | 画框内完整、不被裁、不压到标题 |
| 首页 Bento（若入选） | 1440 / 375 | 与默认示例一致，不贴边 |
| 亮色 / 暗色 | 1440 | 暗色下材质、线条、着色都清楚可见 |
| 颜色主题 | 抽 blue / orange / violet | 主题色跟随、互不撞色 |
| 动画 | 抽 2–3 帧 | 中间帧不难看，计数与状态一致 |

## 6. 交互与动效验收

- 控制台无 hydration 报错（三角函数、随机数、时间在 SSR 与客户端要一致，坐标取固定小数位）。
- 按下 / 拖动不会选中旁边的文字（`select-none` + 鼠标按下时 `preventDefault`）。
- `prefers-reduced-motion` 下静止或瞬时切换；离屏暂停。
- 音效默认关闭，示例打开时同时提供静音入口；偏好存本地、全站共用。
- 键盘可达；装饰性图形 `aria-hidden`，有意义的图形给 `label`。
- 无 JS 时内容完整可见（入场动画用 CSS，不靠 JS 把透明度从 0 拉起）。

## 7. 收尾

```bash
source ~/.nvm/nvm.sh && nvm use
pnpm registry:build && pnpm lint && pnpm registry:lint && pnpm build
pnpm qa:shots <组件名>    # 报告里 0 个问题，截图逐张看过
grep -rIil -f .forbidden-terms --exclude-dir={node_modules,.next,.source,.git} --exclude=.forbidden-terms .   # 必须为空
```

- 改了全局 CSS 不生效时先 `rm -rf .next/cache`。
- 删除示例前 `grep` 全仓引用（博客文章也会引用示例）。
- 提交前 `git status --short`，只 `git add` 本轮自己的文件；格式化工具顺带改到的无关文件要还原。
